# デプロイ運用（本番と開発用）

生徒が毎日使う **本番** と、開発・確認用の **開発環境（プレビュー）** を分ける。

## ブランチの役割

| ブランチ | 用途 | Vercel 上の扱い |
|----------|------|-----------------|
| **`main`** | 生徒向け・実運用のアプリ | **Production**（本番ドメイン） |
| **`dev`** | 日常の開発・検証・中間確認 | **Preview**（プレビューURL） |

- 日々の作業は **`dev` に push** → 自動で **開発用デプロイ（プレビュー）** が走る想定。
- **本番へ反映**するときだけ **`dev` → `main` をマージ**し、まとめてアップデートする。

## 推奨フロー

1. **開発・テスト**  
   - `dev` でコミット → push  
   - Vercel の **Deployments** で `dev` 向けの **Preview** が **Ready** になるまで待つ  
   - 表示される **プレビューURL**（またはチーム用に割り当てたステージングドメイン）で動作確認する  

2. **本番リリース（まとめてアップデート）**  
   - プレビューで問題なければ GitHub で **`dev` → `main` のマージ**（PR 推奨）  
   - `main` へのマージで **Production** がビルド・デプロイされる  
   - 生徒向けURLは **本番ドメイン**のまま（`main` の最新が反映される）

## Vercel 側の設定（プロジェクト設定で確認）

- **Production Branch**: `main`（本番は `main` のみ）
- **`dev` の push**: 自動で **Preview Deployment**（開発用URLが毎回 or コミット単位で発行される）

任意で **Preview 用に固定のサブドメイン**（例: `staging.◯◯.vercel.app` やカスタムドメイン）を `dev` に割り当てると、URL をブックマークしやすい（Vercel → Project → Settings → Domains / Git のブランチ設定）。

## 生徒向けURLと開発用URLの使い分け

- **生徒・保護者に伝えるのは本番ドメインだけ**（`main` がデプロイされた先）。
- **プレビューURL**は開発・塾内確認用。必要なら塾内限定で共有。
- **実装後の動作確認を「毎回同じ安定ルール」で渡す**手順は [verification-handoff.md](./verification-handoff.md)（**localhost 第一推奨にしない**・**dev の Preview をデフォルト**）。

## 注意

- `.env.local` はコミットしない。本番・プレビューとも **Vercel の Environment Variables** に `NEXT_PUBLIC_SUPABASE_*` 等を設定する。
- 本番とプレビューで **同じ Supabase プロジェクト**を向けるか、検証用に別プロジェクトにするかは運用で決める（検証は別DBが安全な場合あり）。
